# 하단 스킬 선택 UI 검증

검증일: 2026-10-14 · Unity Windows 실행 파일과 실제 Chrome 플레이

## 변경

- 모든 아군의 제시 카드 두 장을 하단에 함께 표시한다. 카드 아래에는 초상·체력·정신력·방어 행동·두 행동칸과 연결 대상을 둔다.
- 카드 클릭이 해당 캐릭터를 선택한다. 새 카드는 빈 행동칸을 사용하고, 예약한 카드는 자기 행동칸을 다시 편집한다. 행동칸을 명시적으로 선택하면 그 칸의 스킬을 교체한다.
- 카드에서 예고선·적 부위·아군으로 직접 드래그한다. 기존 행동칸 드래그도 지원한다.
- 불 개수·위력 범위·불씨 비용과 예약 상태를 카드에 표시한다. 실행 버튼을 키우고 연결 수·예약 불씨를 함께 보여 준다.
- 기존 카드 덱·정신력·불꽃·맞불·속성 상성은 공용 Core 규칙을 사용한다.

새 동작 검사에는 실제 `lian:card:1` 형식의 카드 ID, 같은 1스킬 두 장의 별도 예약, 첫 카드 연결 뒤 두 번째 빈 행동 자동 선택, 예약 카드 재편집, 명시적인 행동 교체, 직접 치유 드래그, 비용·동기화 잠금, 드래그 취소와 모달 입력 차단이 포함된다.

Unity에서는 불씨 2로 미나토 2스킬을 예약한 뒤 비용 2인 3스킬이 빈 두 번째 칸에서 비활성화되는 것을 검사했다. 비용 부족이 기존 예약을 자동 교체하지 않으며, 첫 칸을 명시적으로 고르면 환불 예산으로 교체할 수 있다. 미나토의 치유 3스킬은 한 칸을 사용한다.

Unity 캡처 검사는 창이 표시된 상태에서 실행했다. 숨긴 창은 첫 화면의 캡처 텍스처를 만들지 못해 재실행했으며, 표시된 상태의 최종 실행은 모든 검사를 통과했다.

## 실제 플레이와 화면

Unity에서 여섯 카드, 다른 캐릭터 카드 직접 선택, 두 개의 동일 스킬 카드 예약, 실제 LinkDrag의 시작·이동·종료, 예약 카드 편집을 검사했다. 이후 준비·충돌·타격·반동, 접촉 순간 체력과 효과음, 다음 라운드, 승리·보상 저장까지 완료했다. 결과는 `Unity/smoke-result.txt`, 대표 화면은 `Unity/17-skill-bag.png`다.

Chrome은 별도 `Browser/progress.xml`의 1-8 전투에서 검사했다. 여섯 카드를 모두 연결하고 실행해 실제 맞불·피해 연출 뒤 Round 02로 돌아왔다. 잘못된 치유 대상, 빈 곳 드롭, 퇴각 창 뒤의 드래그는 예약을 유지했다. 콘솔 오류·경고는 없었다.

브라우저 SDK는 드래그 도중 Escape를 끼워 넣는 입력 순서를 제공하지 않는다. 이 정확한 순서는 자동 회귀 검사에서 명령이 발생하지 않음을 확인했고, 실제 브라우저에서는 열린 모달 뒤의 드래그가 차단되는 것을 확인했다. 상세 결과는 `Browser/qa-result.txt`다.

1600×900 기준 카드 166×88, 하단 패널 y650~856, 실행 버튼 y768~848로 화면 안에 들어간다. 전장 체력바 끝은 y643으로 패널과 겹치지 않는다. 여섯 연결선과 연결 확정 효과는 측정한 행동칸 중심에서 시작한다. 측정 자료는 `Browser/layout-measurements.json`, 대표 화면은 `Browser/02-six-actions-linked.png`다.

사용자의 기존 Unity·브라우저 저장은 유지했다. 검증 파일·화면과 로그는 이 폴더의 격리 경로에 보관한다.
