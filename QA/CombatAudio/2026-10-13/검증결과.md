# 전투 효과음 교체 검증

2026-10-13. 사용자가 요청한 금속 충돌·짧은 타격·묵직한 강타를 구분했다.

## 적용

- 원본 PCM WAV 8종×3변형=24개. 48kHz·스테레오·16비트. 금속 맞불, 베기, 둔기, 강타, 바람, 방어 준비, 불씨, 파괴를 별도 재질로 만든다.
- 고정된 비정수 금속 공명·충격 잡음·중저역 타격 몸통을 사용한다. 전투 중 주파수가 미끄러지는 필터와 단음 재생을 제거했다. 메뉴 클릭음은 유지한다.
- Unity와 브라우저가 같은 파일을 미리 읽는다. 각 종류의 세 변형을 순환하며 지연 로딩된 소리는 늦게 재생하지 않는다.
- 맞불과 실제 피해의 접촉음은 해당 접촉에서 한 번만 재생한다. 준비·불 공개·회피·파괴는 자기 종류의 소리를 사용한다.
- 음소거와 화면 취소는 재생 중인 전투음을 멈춘다. 최대 8개 소리를 동시에 재생하며 활성 소리 수에 따라 볼륨을 나눠 합산 피크를 제한한다.

## 검증

- 자산24개: PCM 형식, 최고 진폭·클리핑, RMS, DC 오프셋, 시작·끝 진폭0, 세 변형 구분, 소스로 다시 만든 PCM의 SHA 일치를 검사했다. 최고 진폭0.800012, 최소 RMS0.037318.
- 브라우저 음향8개·전투 연출37개·동작40개=85개 검사 통과. 재질 선택, 반복 변형, 읽기·디코딩 캐시, 늦은 소리 방지, 음소거·취소, 8개 제한·합산 볼륨, 접촉 시점과 움직임 간소화를 검사했다.
- 실제 HTTP에서 24개 WAV의 MIME·RIFF 형식과 원본 바이트 일치를 확인했다.
- 실제 브라우저에서24개 WAV 요청과 전투의 충돌·피해·다음 라운드를 확인했다. 자산·콘솔 오류가 없었다. 저장은 격리했고 기존 사용자 저장은 유지했다.
- Unity 소스 컴파일·Windows 빌드 통과. 빌드 전에24개 AudioClip의 존재·스테레오·유효 샘플을 검사했다. 실제 플레이 검사는 미리 읽기, 음소거 상태의 소리 생성 금지, 재생 중 음소거 정지, 준비 중 접촉음0·타격과 반동 시 접촉음1을 통과했다.

실제 브라우저 기록은 `Browser/qa-result.txt`, Unity 결과는 `Unity/smoke-result.txt`에 보관한다. 원본과 제작 기록은 `Art/Audio/README.md`, 제작 코드는 `Tools/generate-combat-audio.py`다.

## 청음

`Art/Audio/combat-audition.wav`는 약6.8초로 바람→금속2개→베기→일반 타격2개→강타2개→장비→불씨→파괴 순으로 재생한다. 이번 자동 검사는 자산과 재생 동작 검사이며, 실제 청음과 소리의 취향 평가는 수행하지 않았다.
