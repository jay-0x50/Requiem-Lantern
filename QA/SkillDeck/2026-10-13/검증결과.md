# 스킬 덱·진행 표시·전투 연출 검증

2026-10-13. Unity 6000.6.0f1 Windows 개발 빌드와 공용 C# 전투 서버를 사용했다.

## 적용

- 캐릭터별 1스킬 3장·2스킬 2장·동기화 후 3스킬 1장. 실제 카드 ID를 가진 두 장 손패, 미사용 카드 유지, 실행 시 소모, 다음 라운드 보충, 버린 카드 재셔플.
- 방어·회피·반격은 별도 선택. 중복 스킬 두 장은 각각 예약하고 동일 카드의 중복 예약은 거절한다.
- 작전실은 완료 구간과 다음 스테이지까지 표시한다. 1-3 완료 후 1-1~1-4를 표시하며 미래 스테이지와 장 탭을 숨긴다. 기록실은 완료 구간만 표시한다.
- 불·어둠을 미정 상태에서 하나씩 공개하고 위력을 쌓는다. 접전의 긴 점화는 라운드당 최대 두 번이다. 상태 문구도 공개가 끝나기 전에는 최종 결과를 노출하지 않는다.
- 리안의 묵직한 준비·타격 정지, 세라의 빠른 진입·되돌아 베기, 미나토·노아의 넓은 궤적을 보강했다. 피해는 권위 있는 전투 이벤트에 따라 접촉 순간 한 번 적용한다.

## 검증

- Core 46개, 캠페인 15개, 브라우저 동작 36개, 전투 연출 33개: 총 130개 규칙·회귀 검사 통과.
- 캠페인 25개 전투 × 난수 시드 0·1·2 = 75회. 동기화 0·양호 점화·실제 손패를 사용하는 AI에서 모두 2~7라운드에 승리했다.
- 실제 HTTP: 두 장 손패, 명시 카드 ID 전달·잘못된 카드 거절·중복 예약 차단·연결 초기화 시 손패 유지, 단계 해금, 후속 대화·첫 보상·중복 요청·재감상·동기화 비용을 격리 저장에서 검사했다.
- 설치된 Unity·UGUI·URP 참조 어셈블리 소스 컴파일 통과. 실제 Unity Windows 빌드 성공.
- Windows 플레이 스모크: 별도 저장으로 27개 실제 화면을 캡처했다. 두 장의 중복 카드 선택·개별 예약, 1-1~1-4만 표시, 점화 시작 시 공개 개수 0·단조 증가·완료 전 체력 유지, 준비·접촉·반동 포즈, 접촉 피해, 라운드 종료 체력 동기화, 첫 보상·저장을 통과했다.
- 브라우저 실제 화면 검증 기록은 `Browser/qa-result.txt`, Windows 결과는 `Unity/smoke-result.txt`에 보관한다. PNG와 검수용 저장 파일은 Git에 포함하지 않는다.

## 확인한 한계

전투 자세는 기존 원화 6포즈와 이동·기울임·무기 궤적을 조합한다. 노아·하이델·인간 적의 세부 공격 원화, 관절 리깅과 정식 효과음은 후속 제작이 필요하다. 이번 75회 시뮬레이션은 초기 AI와 세 난수 조건의 진행 검사이며 모든 수동 플레이 조합의 밸런스를 보장하는 자료는 아니다.
