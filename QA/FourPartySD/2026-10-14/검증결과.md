# 4인 파티와 전투 SD 검증

검증일: 2026-10-14 · Unity Windows 실제 실행과 Chrome 플레이

## 변경

- 기본 전투는 리안·세라·미나토·노아 4명, 하단 카드 8장·행동칸 8개다.
- 메인 스토리 2-4부터 19개 전투 모두 4명이다. 초기 6개 전투는 합류 흐름에 따라 1~3명이다. 3-2의 부상 직후 노아 대신 하이델이 싸우고 3-6부터 노아가 출격한다.
- 아군 5명의 SD 6포즈 PNG와 발·무기 좌표를 별도로 추가했다. 대기·준비·공격·후속·복귀·피격 동안 같은 SD 시트를 사용한다.
- 메인·대화·캐릭터 화면과 카드 초상은 원래 일러스트를 유지한다.
- Unity 아군 몸 높이220px/화면1080px, 브라우저는 같은 비율이다. 작은 몸체와 적의 무기가 실제 접점에서 만나고 원래 발 위치로 복귀한다.
- 4열 카드와 오른쪽 실행 영역을 배치했다. 카드 고유ID, 직접 클릭·드래그, 빈 행동칸 예약, 비용 검사, 모달 취소 규칙을 유지한다.

## 실제 화면

Unity에서 5종×6포즈 전환과 발 유지, 원화 분리,8장 카드 폭166px, 직접 드래그와 맞불, 접촉 순간 체력·효과음1회, 다음 라운드·승리·보상 저장을 검사했다. `Unity/smoke-result.txt`에 결과가 있다.

- `Unity/17-skill-bag.png`: 4인SD와8장 카드.
- `Unity/06b-impact.png`: 세라의 작은 SD 실제 대검 접촉.
- `Unity/03-hub.png`: 메인 화면의 기존 큰 리안 원화.

Chrome에서는 격리된8128저장으로3-6을 플레이했다. 메인·노아 인물창·대화의 원화를 확인한 뒤4인SD와8장 카드를 표시했다. 노아의 서로 다른 동일1스킬 두장을 예고선과 팔에 직접 드래그해 각 행동칸에 예약했다. 측정한 행동칸 중심에서 연결선이 시작한다. 실제 SD 근접 동작과 조기 체력 차감 없음, Round02의4인SD복귀를 확인했다.

대표 화면은 `Browser/04-four-party-planning.png`, `Browser/06-sd-melee.png`, `Browser/08-round-two.png`다. 브라우저 접촉 순간은 짧아 별도 캡처를 확보하지 못했으며, 접촉 위치는5종×양방향10맞불 자동 검사와 Unity 실제 접촉 캡처로 확인했다.

2-9에서는 하이델 포함4인과 인간 보스 엘렌의 기존 그림을 확인했다(`Browser/10-heidel-human-boss.png`). 콘솔 오류·경고는 없었다. QA호스트는 식별 후 종료했고 검수 탭은 최신8127프리뷰로 전환했다.

테스트는 격리 저장을 사용했다. 기존8127은 `four-party-sd-v6`로 갱신했으며 개인 저장 경로를 유지한다. Windows 실행 파일은 `Builds/Windows/RequiemLantern.exe`다.

## 제작 기록

SD 시트는 built-in image_gen으로 원화를 참조해 제작했다. 세라·하이델은 포즈 간격을 추가 보정했다. 최종 Resources PNG를 직접 소비하며, Python은 알파 읽기와 좌표 JSON 작성에만 사용했다. 프롬프트와 채택 출처는 `Art/Combat/SD/`에 보관한다. 중간 프레임·관절 리깅은 후속 범위다.
