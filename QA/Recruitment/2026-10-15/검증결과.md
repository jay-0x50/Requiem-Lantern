# 기본 지급·픽업 소환·편성·테스트 쿠폰 검증

2026-10-15 (한국 시간). 실행 버전: `recruitment-v12`.

## 구현

- 기본 소유와 편성은 리안 ★5, 미나토·하이델·카이 ★4다. 세라·노아는 미보유로 시작하며 모집으로 얻는다. 이야기 속 등장과 플레이어 소유를 분리했다.
- 리안·세라·노아 픽업을 선택하고 1회 또는 10회 소환한다. ★5 기본 0.8%, ★5 중 픽업 50%, 80회 이내 ★5 확정과 비픽업 뒤 다음 ★5 픽업 확정을 적용한다. 배너 변경·재시작에서도 천장과 보증이 이어진다.
- 보유 동료의 네 자리를 교체하고, 그 편성으로 실제 캠페인에 출격한다. 미보유 편성·동기화는 거절한다.
- 두 테스트 쿠폰은 재화 또는 재료를 각각 9,999,999개 지급하고 저장당 한 번만 사용한다. 잘못된 입력·중복·한도 초과와 저장 실패를 처리한다.
- 카이의 기존 원화를 유지하고 투명 SD 6포즈를 추가했다. 생성 도구의 간격 보정 후 픽셀은 편집하지 않았으며 알파를 읽어 좌표만 작성했다.

Core는 79/80 경계·조기 ★5 천장 초기화·0.8%/50% 경계·비픽업 풀의 균등 구간·배너 간 보증·10회 중간 상태·중복 조각·이관·저장 난수·실제 저장 실패 복원과 동일 재시도를 검사한다. 전투용 난수는 모집과 분리했다.

실제 HTTP에서는 저장 재시작, 10회 비용과 결과, 쿠폰 중복 거절, 막힌 저장 경로에 의한 추첨 복원, 80회째 보증과 새 획득 동료의 편성·1-2 출격을 확인했다. 마지막으로 동기화의 저장 실패도 재료·성장과 현재 전투의 동기화 표시를 복원하도록 맞추고 같은 격리 HTTP 검사로 확인했다. 이 검사는 사용자 저장을 쓰지 않았다.

Unity 검수는 실행 빌드의 UI 이벤트와 실제 서비스·저장 경로를 사용했다. 첫 검수에서 발견한 쿠폰 오류 문구 잔류와 재료 지급의 불필요한 +0 재화 알림을 수정한 뒤, 최종 빌드에서 해당 두 항목만 다시 검사했다. 결과를 닫는 공용 경로와 갱신을 확인했으며 물리 Escape 키 입력 자체를 자동 검수했다고 주장하지 않는다.

실제 Chrome에서는 미보유 제한·확률표·쿠폰·노아 신규 획득·10회 중복·편성 저장·재시작·출격·카이 SD 접근·다음 계획 복구를 확인했다. 마지막 쿠폰 영역의 전체 화면 배치도 검수했다. 콘솔 오류가 없었으며 격리 탭과 호스트를 종료했다.
