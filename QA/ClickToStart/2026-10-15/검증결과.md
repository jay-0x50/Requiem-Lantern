# 클릭 투 스타트 타이틀

2026-10-15 (한국 시간). 프리뷰 실행 버전: `click-to-start-v11`.

## 변경

- 저장 상태에 따라 달라지던 큰 시작 버튼을 없애고, 하단 중앙에 ‘화면을 클릭해 시작 / CLICK TO START’를 표시한다.
- 타이틀의 일반 영역 클릭과 Enter·Space를 하나의 시작 경로로 처리한다. 첫 실행은 기존 도입 이야기, 기존 진행은 등대 요새로 진입한다. 저장 구조와 진행 기록은 변경하지 않는다.
- 설정은 우측 상단의 작은 버튼으로 연다. 설정 입력이나 복귀 입력이 시작으로 이어지지 않게 분리한다.
- 시작 문구는 은은하게 밝아지며, 움직임 줄이기에서는 고정한다. 배경·로고·세계관 문구는 유지한다.

## 로컬 프리뷰

`Start-Preview.ps1 -NoBrowser`로 사용자 포트 `8127`을 갱신했다. Host 빌드 경고·오류 0개이며, 읽기 전용 조회로 실행 버전과 새 타이틀 코드가 제공되는지 확인했다. 실제 플레이 검수는 별도 저장을 사용한다.

## Preview 검수

- 타이틀 입력 대상 4개와 전체 Preview 회귀 93개 통과. 저장 여부와 무관한 문구, 1-1 단일 진입, 눌린 시작 키의 첫 대사 넘김 방지, 설정 입력 분리를 확인했다.
- 격리 포트 `8128`의 실제 Chrome에서 기존 진행의 Enter·일반 영역 클릭 → 등대 요새, 새 진행의 Space → 1-1 첫 대사 `01 / 08`을 확인했다.
- 설정의 Enter·Space·Escape·뒤로가기가 게임 시작으로 이어지지 않았다. OS 움직임 간소화가 켜진 환경에서 프롬프트의 애니메이션은 `none`이었다. 게임 설정의 움직임 끄기도 적용됐다.
- 콘솔 오류 0개. QA 탭과 격리 호스트를 종료했다. 사용자 진행 기록은 변경하지 않았다.
- 세부 결과: [browser-checks.json](Browser/browser-checks.json). 최종 타이틀은 `Browser/01-title-click-to-start.jpg`, 첫 진입은 `Browser/04-fresh-space-first-scene.jpg`다. 스크린샷과 격리 저장은 로컬 QA 자료로 Git에서 제외한다.

## Unity 검수

- 전체 소스 컴파일과 최종 Windows 빌드 통과. 별도 `--title-smoke` 실행은 종료 코드 0으로 마치고 새 화면 5장을 생성했다.
- 실제 UGUI raycaster로 일반 영역은 시작 입력, 설정 버튼은 별도 설정 입력을 받는지 확인했다. 누른 화면과 뗀 화면이 다르거나 소유하지 않은 포인터 해제는 시작하지 않는다.
- 최초 진입은 1-1 첫 이야기, 저장된 프롤로그 완료 상태는 등대 요새로 이동한다. 시작 입력 중복과 설정 포커스·복귀 입력을 차단하고 움직임 줄이기에서 문구 밝기를 고정한다.
- 기존 저장의 파일 바이트·재화·이야기 완료 상태가 유지되는지 격리 저장으로 검증했다. 물리 키보드 자동 조작 대신 실제 빌드의 공용 키 처리 경로에 입력을 전달했다.
- 결과: [smoke-result.txt](Unity/smoke-result.txt). 최종 타이틀은 `Unity/01-title-click-to-start.png`, 설정은 `03-settings-separated.png`, 기존 진행은 `05-returning-player-hub.png`다.
